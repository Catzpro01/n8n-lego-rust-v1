## 3. Invariants & Proof of Conformance
1. **State Ownership (`token-consumption-counters`)**:
   - Manages bounded token and execution duration consumption counters partitioned by `(tenant_id, session_id)`.
   - Tracks prompt tokens, completion tokens, total tokens, execution duration ms, operation steps, and estimated dollar costs.
   - Computes real-time remaining quotas and issues proactive warnings upon crossing safety threshold ratio (default 80%).
2. **Fail-Closed Multi-Tenant & Multi-Scope Boundary Isolation**:
   - Budget operations validate matching `tenant_id` and `scope_id`.
   - Tenant A cannot consume Tenant B's budget: two tenants using the identical `session_id` remain completely isolated.
   - Missing or empty tenant/scope fails closed with typed error (`EmptyTenantId`, `EmptyScopeId`).
3. **Reservation & Reconciliation Semantics**:
   - Pre-flight reservation via `reserve_budget` holds temporary lease quota.
   - Post-execution reconciliation updates actual consumption, unreserves hold, and releases unused amounts.
   - Over-consumption beyond total budget rejected fail-closed with `TokenLimitExceeded` / `ExecutionTimeExceeded`.
4. **Generation Fencing & Stale Write Rejection**:
   - Session tracks monotonic `generation: u64`.
   - Stale checks, reservations, consumptions, or releases with lower generation are rejected fail-closed with `BudgetError::StaleGeneration`.
5. **Duplicate / Idempotency Protection**:
   - Repeated reservations with matching `reservation_id` return idempotent `ReserveBudgetResult { is_duplicate: true }`.
   - Repeated consumption with matching `idempotency_key` returns idempotent `ConsumeBudgetResult { is_duplicate: true }` without double-charging budget.
   - Duplicate release of already released reservation fails closed.
6. **Bounded State & Capacity Governance**:
   - Enforces `max_active_reservations_per_session` (50), `max_sessions_per_tenant` (200), and `max_total_sessions` (1,000).
   - Capacity exhaustion rejects fail-closed with `BudgetError::CapacityExceeded` without overwriting active reservations.
   - Deterministic cleanup via `cleanup_expired_reservations`.
7. **Sensitive Credential Protection (Secret Redaction)**:
   - Automated in-flight redaction scans for API keys (`sk-...`, `ghp_...`), bearer tokens, and passwords.
   - Replaces credentials with `[REDACTED_API_KEY]` and `[REDACTED]` prior to diagnostic logging or metadata persistence.
8. **Restart / Recovery & Memory Consistency**:
   - Reinitialization via `reset_session` cleanly resets consumed counters while strictly advancing generation.
   - Zero phantom data, zero negative remaining budget balance.
9. **Zero Private Cross-Sub-LEGO Imports**:
   - 0 imports from other Sub-LEGO private modules inside `lego/`.
   - Communication mediated exclusively through typed contracts and public ports.
