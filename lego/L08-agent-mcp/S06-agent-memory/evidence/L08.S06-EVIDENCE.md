## 3. Invariants & Proof of Conformance
1. **State Ownership (`conversation-history-chunks`)**:
   - Manages bounded conversation history chunks indexed by `(tenant_id, session_id)`.
   - Each chunk tracks `chunk_id`, `session_id`, `conversation_id`, `tenant_id`, `scope_id`, `sequence`, `generation`, `role`, `content`, `token_count`, `byte_size`, `created_at_ms`, `updated_at_ms`, `expires_at_ms`, and `metadata`.
   - Guaranteed deterministic chunk identity: `chunk:{tenant_id}:{session_id}:{sequence}:{generation}`.
2. **Fail-Closed Multi-Tenant & Multi-Scope Boundary Isolation**:
   - Store and retrieve strictly validate matching `tenant_id` and `scope_id`.
   - Cross-tenant queries return strictly empty/denied: two tenants using the identical `session_id` remain completely isolated.
   - Missing or empty tenant/scope fails closed with typed error (`EmptyTenantId`, `EmptyScopeId`).
3. **Chunking & Capacity Governance**:
   - Enforces maximum chunk size limit (`max_chunk_size_bytes`, default 64 KB). Chunks exceeding this limit are rejected fail-closed.
   - Bounded session capacity: enforces `max_chunks_per_session` (default 100), `max_bytes_per_session` (default 256 KB), and `max_tokens_per_session` (default 32,768).
4. **Deterministic Eviction & Retention**:
   - Automatically cleans up expired chunks (`now_ms >= expires_at_ms`).
   - Eviction policy prioritizes evicting oldest non-system chunks while strictly protecting `MemoryRole::System` directives.
   - If capacity remains exceeded after non-system eviction, store fails closed with `CapacityExceeded`.
5. **Transactional Eviction (No Silent Data Loss)**:
   - Eviction operates on draft copy; if new chunk cannot fit, rejection with `CapacityExceeded` leaves existing session state 100% intact.
6. **Generation Fencing & Stale Write Rejection**:
   - Session tracks monotonic `generation: u64`.
   - Stale writes or updates with lower or equal generation are rejected fail-closed with `MemoryError::StaleGeneration`.
   - Stale deletes with lower generation are rejected with `MemoryError::StaleGeneration`.
7. **Duplicate Store & Idempotency**:
   - Repeated store invocations with matching role, content, and generation return idempotent `MemoryStoreResult { is_duplicate: true }` without allocating redundant chunks or advancing sequence counters.
8. **Sensitive Credential Protection (Secret Redaction)**:
   - Automated in-flight redaction scans for API keys (`sk-...`, `ghp_...`), bearer tokens (`Bearer ...`), and passwords (`password=...`).
   - UTF-8 byte-boundary safe implementation prevents indexing panics on multi-byte characters and handles quoted secrets with spaces.
   - Replaces credentials with `[REDACTED_API_KEY]`, `[REDACTED_BEARER_TOKEN]`, and `[REDACTED]` prior to memory persistence.
9. **Update Bounds Enforcement**:
   - Updating chunks checks `max_chunk_size_bytes` and session `max_bytes_per_session` / `max_tokens_per_session`.
10. **Restart / Recovery & Memory Consistency**:
    - Hard reset cleanly purges in-memory session tables.
    - Verification confirms 0 phantom data chunks and zero sequence regression across restarts.
11. **Zero Private Cross-Sub-LEGO Imports**:
    - 0 imports from other Sub-LEGO private modules inside `lego/`.
    - Communication mediated exclusively through typed contracts and public ports.
