## 2. What P5.8 adds

* **`n8n-lego credentials` — the operator entrypoint that did not exist.** Before P5.8, key rotation, rotation recovery, backup and quarantine restore were library functions with no way for an operator to run them. `src/auth/credential-operator.mjs` (verbs) + a minimal `bin/n8n-lego.mjs` wiring. No new cryptography, no second vault. Mutating verbs refuse while the server's address:port is bound; nothing ever mints a key over sealed data; output never contains material. Declared scale-out exception (S3, accepted) for the operator-named backup file.
* **Cross-slice certification suite** `apps/n8n-lego/test/lego-p5-certification.test.mjs` — 51 tests, mostly against the real server as a separate process with file storage and **debug** logging.
* **Benchmark tool** `apps/n8n-lego/tools/p5/p5-certification-benchmark.mjs` (baseline vs P5, reproducible).
* **Operator runbook** `docs/n8n-lego/P5-SECURITY-OPERATOR-RUNBOOK.md`.
* No new contract row: the lock stays at **100 rows**; P5.8 closes the lock by asserting it (§3).

## 5. Findings recorded by certification (not hidden)

1. **The P5.3 decision cache is not on the REST request path, and on this machine it does not pay for itself on the cheap path**: a warm hit (438 ns p50) is not faster than uncached `authorize` ALLOW (384 ns p50). REST enforces scopes through `compat/scopes` from the same canonical `roles.json`; §3 row 2 proves the two paths never disagree. The engine is used by SecretRef and machine identity. *Debt:* route REST authorization through the engine only when a need (per-resource or tenant policy) makes it worthwhile; drop or keep the cache on measured evidence.
2. **SecretRef is not yet used by execution** (carried from P5.4): the engine never touches credentials, so no secret can reach an execution record (§3 row 4 measured this), but nodes cannot yet consume credentials through SecretRef either.
3. **CSRF double-submit token is opt-in** (P5.2 contract, forced by the pinned upstream editor, which never sends it). Always-on defence: Origin/Referer validation + `SameSite=Lax`. §3 row 3 pins both halves.
4. **A finished rotation makes older credential backups unrestorable** (by design: crypto-shredding). Now surfaced by the CLI warning, the runbook, and a test.
5. **No supported password recovery without a mail transport**, and no admin-initiated reset (user management unsupported).

## 7. Remaining technical debt of the P5 plane

* P5.4: SecretRef not wired into execution; tenant is always `default`; credentials created before P5.4 have no `ownerId`.
* P5.5: per-host local keyring (declared scale-out exception, blocking once storage is shared — P8/P11); rotation work-list is an O(n) filter; no external KMS.
  - P5-M04 measured the O(n) work-list filter against the O(n) replaceAll persist: on the production file-backed storage the **persist** (full-file rewrite per batch, O(n²/batchSize) I/O) dominates the scan by 5–15×, so the work-list is **not** indexed. The real rotation debt is the persist, not the scan — see `P5-M04-EVIDENCE.md`.
* P5.6: no mail transport; limiters, reset tokens and sessions are process-local; IP limiter keys on `remoteAddress` only; MFA enforcement deferred.
* P5.7: no `/api/v1` mount (the authenticator exists, nothing calls it); no REST/UI and no ownership transfer for service principals; key revocation deletes instead of tombstoning; members (not only admins) may create service principals within their own grant.
* P5.8: decision cache unused on REST (finding 1); operator CLI is single-host and offline-only.
